# 2026-09-23

## DatePicker 日期引擎改为复用 react-day-picker

用户指令链：「那就使用react-day-picker」→「继续，要求能用、好用、没有问题」。

### 事实核查（先答后改）
- 原 PC 月历 **100% 自研**：`buildMonthGrid` 造网格、`CalendarCell` 造补位格、自己算区间内含
  （跨月补位 / 跨年 / `weekStart` 轮转 / 区间倒序四类边界）。
- **React 版 `@radix-ui` 没有 Calendar / DatePicker 原语**（只到 `Popover`）；`radix-vue` 有但属 Vue 生态。
  React 侧现成件 = `react-day-picker`（shadcn 的选择）或 React Aria。
- 选型：MUI X 四重冲突（Emotion vs Tailwind / Material vs Vant / 根部 `LocalizationProvider` vs
  copy-paste 自包含 / +4~5 依赖 vs 白名单）→ 定 **rdp v10.0.1**。

### 落地
- `components/pc/date-picker.tsx` 重写：rdp 只当日期引擎（网格 + `modifiers` 上色），
  本库保留渲染层、`data-slot` / `data-*` 契约与键盘。
- **键盘自持**：rdp 内置巡航依赖焦点落在日期格上，与本库「触发器是可输入框、焦点须留面板」冲突
  → 日期格 `tabIndex={-1}` + `onMouseDown preventDefault`，方向键 / PgUp / PgDn / Home / End / Enter
  由面板级 `handleKeyDown` 接管。
- **值语义不复用 rdp**：只取 `onDayClick` 那一天；区间仍由 `displayRange` 推导
  （rdp 的 `addToRange`「在已选区间上调整」≠ Vant「再点即重选」）。
- `data-mode` 覆盖：rdp 自己往 root 写 `data-mode={props.mode}`（single/range），
  自定义 `Root` 里改回 `pc`（契约 20）。

### ⚠ 本轮抓到的静默失效（四门全绿也抓不到）
- 上游源码：`useSingle` / `useRange` 都是 `const selected = !onSelect ? internallySelected : initiallySelected;`
  → **不传 `onSelect` 即非受控**：内部 state 首帧从 prop 播种后忽略一切 prop 更新。
- 症状：PC 区间悬停预览不动（状态已 `{09-20, 09-25}`，DOM 仍是上一帧的带）、第二次点选错位。
- 排查路径（可复用）：① 读 DOM 的 `__reactProps` 确认 `onMouseEnter` **确实挂在 button 上**；
  ② 直接调用该 prop，DOM 仍不变 → 排除事件投递；③ 在 rdp 的 `DayButton` 里打印 `modifiers`
  → `range_start` 是**上一帧**的日期 → 断定 rdp 内部给了旧值；④ 读上游 `useRange.js` 命中 `!onSelect` 分支。
- 修法：`RDP_NOOP_SELECT` 空实现把开关拨到受控侧，选值语义仍归 `onDayClick`。
- 教训：**把状态交给上游时，别按 prop 名字假定「传了 `selected` 就是受控」，去读源码找开关。**
